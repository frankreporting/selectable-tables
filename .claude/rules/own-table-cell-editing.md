# The plugin's own table: editing, clearing and formatting cells

Moved here from `CLAUDE.md` on 2026-11-26. This file loads by itself when a session opens a file under `paths`. When a change alters what it says, update it here.

**Editing a cell (STA-81).** A double-click on a cell, a click on the cell already selected, Enter on a selected one, or typing on it (*Typing over a cell*, in `own-table-keys.md`), opens it (a click, with *Click to select a cell* off; *Clicks*, in `own-table-keys.md`) in Obsidian's own Markdown editor, borrowed (`cell-editor.ts`), inside the drawn cell, with the drawn text hidden as Obsidian's cell hides it (item 8 of the first list). One cell is open per note (`openCells` in `layout.ts`). The note's text always wins (`open-cell.ts`):

- **Each change in the cell goes to the note at once,** one change in the note for each, with the change's user event, so the note's history groups typing as for Obsidian's cell, and only the characters that changed: a write over the whole cell had Undo restore a range whose start is past its end, which crashed the spike. A pipe is written `\|`, and a line break `<br>` outside code (`toCellEditor` and `toCellSource` in `table-text.ts`, one set of rules both ways). A table Obsidian wrote is padded as Obsidian pads it, read from 1.15.1's `updateCell`: its column as wide as its longest text and two spaces, every row's cell in it and the delimiter row written again when that changes. Any other table keeps its spacing, and only the cell changes, its pipes kept while the text fits, with a space kept after a backslash at its end, which would escape the pipe; a short row gets the cells it lacks (`cell-write.ts`). Obsidian's cell doesn't trim a cell as it closes either: it only marks its own model malformed.
- **The note's selection follows the cell's caret,** without scrolling, with `writesCell`, which the check on key moves and the caret rule leave alone. Obsidian's editor commands act at the note's selection, as for its own cell (Cmd+B, Cmd+K). A change that lands right inside the open cell's text is taken into the cell and written as the cell writes, escaped and padded (`reconcile`, a transaction filter), as Obsidian's table takes it into its open cell: so Insert horizontal rule writes `<br><br>---<br>` rather than splitting the row, and Bold keeps the column's pipes in line.
- **A change from anywhere else** (Undo from the cell or the note, Sync, a second pane, another plugin) comes into the cell, with its caret where the note's selection is, only after a composition in the cell ends. Such changes come often: on a long note, Obsidian's parser sends one, with no text, about 120 ms after each key. A space typed at the cell's end is only padding to the note, which trims it from the cell's text, so while the cell's text stands, the note's selection is read back by the cell's own text, and a caret after that space stays after it (Brian's hand check, 11/21). A selection that leaves the cell closes it, and in another cell of the table the caret rule selects that one. A cell whose row went in a rewrite of the table opens again in the same column of the row its line went to (`movedRow` in `cell-write.ts`), else at the same row: Sync and a second pane send a row put in or taken out above the cell as one change that rewrites the cell's line too, and the cell stays in its row's text, where Obsidian's own table closes it (STA-106). A table found anew is matched by where it starts, then by its place among the note's tables. A redraw of the open row redraws its other cells in place, never moving the row or the cell, which would take the keyboard from the editor; for the same reason the open row stays in the page however far the note scrolls, among spacers of its own, and the cell takes its focus back, without scrolling, when CodeMirror puts its block back in the page or moves it into a new box around a table's blocks. A rewrite that takes the cell's row gives the note the keyboard; the cell's own focus events say whether it had it, since an editor out of the page no longer does.
- **Its keys,** while no suggestions show (STA-9): the arrows, Cmd with them, Page Up and Down, Cmd+Home and End, and Ctrl+↑/↓ on a Mac stay in the cell's text. ← and → stop at its ends, ↑ and ↓ on its first or last line go to its start or end, as in any text box, and the jump keys go to its start or end (`cursorDocStart` and `cursorDocEnd`: CodeMirror's own Page Up and Down would move by a page and scroll the note), Shift selecting with each. Moving around the table is the selected cell's, after Escape. Tab and Shift+Tab go to the next and previous cell, and Enter to the cell below, each with its text selected, as Obsidian's cell has them (read from 1.15.1); at the table's ends they do nothing, held or not, so no key adds a row. Shift+Enter is a line break. Cmd+Z and Cmd+Shift+Z run the note's undo and redo, as Edit › Undo and the palette's do. Escape goes through `escapeCell`: the cell closes and is selected, and Escape again selects the table. The plugin's binding for the jump keys (`cellJumpKey`), which Obsidian loads into the borrowed editor at a higher precedence, stands aside in the plugin's cell (`inOwnCell`); on Obsidian's table it still closes the cell and jumps, and Obsidian's cell keeps its own arrows.
- **The private calls,** in `cell-editor.ts` only, each checked before use (`missingPiece`): (1) the base Markdown editor class, the first class up from `MarkdownView.editMode` that has `editTableCell`, made with `(app, containerEl, owner)`; (2) its `set`, `cm`, `editorEl`, `sourceMode`, `buildLocalExtensions`, `onUpdate` and `destroy`, besides the public `load` and `unload`; (3) the `activeCM` getter of `editMode` and the `inTableCell` getter of the note's `Editor`, answered for the open cell with instance getters, so `focus` and `exec` reach it and Toggle checkbox, lists, quotes and callouts leave the table's row alone, taken off as the plugin unloads; (4) `app.workspace.editorSuggest.isShowingSuggestion()`, so suggestions take the cell's keys first; (5) `window.CodeMirror.getMode` with `hypermd` and the options of Obsidian's own cell's language, since the base class adds no Markdown language and without one nothing renders; (6) the base editor's own `editor`, Obsidian's `Editor` over the cell's view, which formats the open cell (*Formatting cells*, below). Relied on, not called: Obsidian loads plugins' editor extensions into the borrowed editor, the plugin's own included, which stand aside there (`inOwnCell` in `layout.ts`; `language.ts` gives that editor no copy).
- **The fallback:** at the first cell opened after Obsidian starts, a missing piece, or an error building the editor, has cells open in a plain CodeMirror editor of the plugin's own until Obsidian restarts, and a notice says so once. Markdown shows as text there until the cell closes, with no suggestions or paired brackets; keys, writes, undo and input methods are the same code, and it gets the same `inTableCell` answer while those getters exist. The check script forces it with `forcePlain`.
- **How the check script notices:** *Own 50* to *Own 64*, open cells with real presses and keys through the window's debugger: the editor is borrowed, Markdown hides as you type, suggestions take the keys first, the note's editor answers for the cell, the keys staying in the cell's text, Enter and Tab between cells and at the table's end, Obsidian's cell keeping its keys with the switch off, Escape's two steps, clicking out, Stock's escaping and padding, undo from the cell and the note, edits from elsewhere and rewrites, input methods, scrolling away, the fallback forced and each private piece taken away in turn named, the right-click menu, then 3 × 200 seeded random steps. `window.__checkCellsOnly`, with `__checkOwnOnly`, runs only them. `.dev/measure`'s `measure-sta81.js` times the cell against Stock, and `compare-sta81.js` plays the same input in both and lists what differs; `.dev/themes/sta81/open-cell.cjs` compares an open cell with Obsidian's under the default theme, Minimal and Baseline, headless.
- **A press** puts the caret where it landed in the drawn text, counted in visible characters and found again in the editor's drawn text, where Live Preview hides the Markdown the same way, else where the press is in the editor. On a phone the editor takes the focus inside the tap's own handler, which is what has iOS show the keyboard.

**Clearing, cutting and pasting cells (STA-117).** Backspace, Delete, Cut and Paste on a selected cell or a range of cells of the plugin's table, as Obsidian's range has them (read from 1.15.1's `deleteSelection`, `copySelection` and `pasteSelection`). `decide.ts`'s `clearCells` gives Backspace and Delete their action on the plugin's table, and `extension.ts` reaches the writes through `setCellEdits`, which `tables.ts` sets: on Obsidian's table these keys still do nothing.

- **One cell:** Backspace and Delete empty it, Cut copies its text as Copy does then empties it, and Paste writes the clipboard's text over it, as a paste into its open cell would (1.15.1's `handleDataTransfer`: the plain text under Obsidian's own HTML, else the Markdown, else the HTML as Markdown through the public `htmlToMarkdown` while the vault's Editor › Auto convert HTML is on, read through the vault's private `getConfig` only where it's there, else a link from a link's address, else the plain text), trimmed. It's written as the open cell writes (`writeCell`), a pipe as `\|` and a line break as `<br>`, so a table spaced by hand keeps its spacing. The cell stays selected.
- **A range:** `editCells` in `table-edits.ts`, from the text, as Obsidian writes the whole table: across every column the rows go, across every row the columns, across both the table; else its cells are emptied, each emptied column as wide as its longest text and two spaces again. The range ends, and a cell is selected where Obsidian puts its focus: the range's first cell after Backspace and Cut, its last after Delete, or beside the rows or columns that went (Obsidian adds a blank line above or below when the header or the last rows go, for its caret; here a cell stays selected, so nothing is added). Cut gives Copy's four forms first. Plain text pasted on a range does nothing, as Obsidian's read-only open cell takes nothing.
- **Pasting cells:** `obsidian/table` on the clipboard (*What it relies on*, item 17), read only in its shape (`readTableData`), pastes cells, from Obsidian's table or the plugin's, over the cells from the selected one, the range's top left, or an open cell on, the table growing rows and columns to fit. Onto the header row the pasted columns take the clipboard's alignments; elsewhere only new columns take any, from the clipboard's first, as 1.15.1 has it. Each pasted column is as wide as its longest text and two spaces. The last cell pasted is selected, or opens, after a paste into an open cell: the open cell's editor takes `obsidian/table` first (`pasteCells` on its setup), and leaves anything else to its own paste. A pasted cell's text has its raw pipes and line breaks escaped, and a freeze mark in it is left out.
- **The freeze mark** stays in its header cell when that cell is emptied or written over, before what's written, and goes to the new header's first cell when its row or column goes, as for Delete row.
- **Undo** takes each back in one step (`isolateHistory`), and the writes carry `writesTable` (`cells`), which the edit guard lets through. After Undo the table is selected whole, as before the edit, and the cell selected afterwards stays selected while it's in the table.
- **Where it differs from Obsidian's table:** Obsidian opens a cell afterwards; here it's selected, since keys don't open cells on the plugin's table. One selected cell clears and pastes too, which Obsidian's table has no way to select.
- **How the check script notices:** *Own 134* to *Own 145*: the test plan's steps on *Seed trays*, *Two report tables* and *Plants*, cells copied both ways between Obsidian's table and the plugin's, each range action against Obsidian's own range dragged and keyed with the switch off (the same text, the table spaced by hand included), 60 seeded random steps against a model of Obsidian's range, and Backspace on 1,000 whole rows, Cut over all of *Table 2000 by 12* and Paste of 2,000 rows, timed. `window.__checkCellEditsOnly`, with `__checkOwnOnly` and `__checkCellsOnly`, runs only them. *Own 39* and *Own 115* no longer check that Cut and Paste do nothing.

**Formatting cells (STA-16).** Bold, Italic, Strikethrough, Highlight, Code, Math, Comment and Clear formatting on a selected cell or a range of cells of the plugin's table, as on Obsidian's range, and in its open cell, in `formatting.ts`, with the cells' text in `format-cells.ts`. The note's tree has nothing inside the plugin's tables (item 2 of the list in `own-table.md`), so Obsidian's methods (item 18) can only add formatting there, and on a selected cell the edit guard stops them. So each note's `Editor`, while the plugin draws its tables, gets the four as instance methods, which hand over; they're taken off as the switch goes off or the plugin unloads:

- **On a selected cell or a range,** Obsidian's own method runs on a stand-in for the `Editor`: its document is the table cut down to the cells' rows and columns, header and delimiter kept, a freeze mark left out, parsed to its end by Obsidian's own Markdown language for notes (`knownLanguages`), as it parses its own table, and its formatting ranges are the cells' text. Each cell on a line of its own, parsed by the cell editor's language, read a `#`, `- ` or `>` at its start as a heading, list or quote marker, which Clear formatting took out. So every rule is Obsidian's: the first cell decides, a highlight's colors, Comment coming off only when every cell has one. The changes it dispatches are read back cell by cell and written as an open cell writes (`writeCells` in `cell-write.ts`): a table Obsidian wrote padded again column by column, any other keeping its spacing. One transaction with `writesTable` (`cells`) and `isolateHistory`, and the cell or range stays selected. Where the stand-in can't run, nothing changes and a notice says so once.
- **In an open cell,** the cell's own `Editor` (*Editing a cell*'s piece 6) runs it, reading the cell's own tree, and its change reaches the note as typing does. In the plain editor, which has no Markdown language, Obsidian's method runs as before and can only add.
- **Anywhere else,** Obsidian's own method runs: on Obsidian's table, in text, on a table selected whole (STA-6). Commands that change lines, such as Toggle checkbox and lists, are untouched, so the guard still stops them on a selected cell.
- **Where it differs from Obsidian's table:** a table Obsidian wrote is padded again, as an open cell pads it; Obsidian's range leaves the padding as it was.
- **How the check script notices:** *Own 146* to *Own 156*: what it relies on, the test plan's steps on *Seeds*, *Plants* and *Spaced by hand*, three sequences of commands on ranges against Obsidian's own range with the switch off, the line commands staying quiet, Bold on 1,999 cells of *Table 2000 by 12*, timed, 40 seeded random steps, and Cmd+B on Obsidian's table with the switch off. `window.__checkFormattingOnly`, with `__checkOwnOnly` and `__checkCellsOnly`, runs only them. *Own 39* and *Own 115* now check that Toggle comment and Bold act on a selected cell and a range.

**Following links (BMT-59).** Obsidian's four link commands on the plugin's table, in `links.ts`, answering the `open-link` event they send (item 19 above), as Bases does, on the note's content in the capture phase:

- **A selected cell:** the event's target is the note's content. Its links are read where the cell is drawn on top (`drawnCell` on the model: a pinned copy where it pins, else its own), `a.internal-link` and `a.external-link`, not inside an embed (`pickLinks` in `cell-links.ts`), with `data-href`, then `href`. One opens at once, a note's through `app.workspace.openLinkText` with the note's path and the event's pane, a web address through `window.open`; several show a `Menu` right below the cell, each item its address cut to 100 characters (`menuTitle`), as in Bases. None, a range of cells, a table selected whole, or a cell whose row isn't in the page: the event is left alone, so nothing happens. The note's text, the selected cell and the open cell are untouched.
- **An open cell:** the event's target is in the cell's editor. The cell's own `Editor` (*Editing a cell*'s piece 6) finds the link at its caret with `getClickableTokenAt(getCursor())`, reading the cell's own tree, and the note's `MarkdownView.editMode.triggerClickableToken(token, paneType)` opens it, as Obsidian's command does in its own cell. Both private, checked before use: without them, or in the plain editor, nothing happens.
- **The keys stay Obsidian's:** the commands run from Obsidian's hotkeys, so changed hotkeys work. The plugin binds plain Enter only, so Option+Enter neither opens the cell nor types over it.
- **How the check script notices:** *Own 186* to *Own 200*, the test plan's steps in *Links in cells* with real keys through the window's debugger, Obsidian drawing its menus, and spies on `openLinkText` and `window.open` that record every open instead of making it: the event's target and pane, Fern in each of the four panes, Balcony's menu under the cell, Escape and a pick, Mint and Porch's web links, nothing on Basil, a tag, a picture, the table selected whole and a range, Yard, Fern's open cell, Beds' pinned header, a pinned cell deep in *Frozen table 2000 by 12*, timed, and Obsidian's own open cell with its tables left to Obsidian. `window.__checkLinksOnly`, with `__checkOwnOnly` and `__checkCellsOnly`, runs only them.
